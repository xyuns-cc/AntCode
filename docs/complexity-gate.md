# Python 复杂度增量门禁

## 目标

仓库存在一批历史复杂度债务，直接全量启用 Ruff 严格规则会让 CI 永久失败；按目录忽略又会让同目录的新代码继续绕过检查。本门禁使用函数级、数值化基线，只允许债务保持或下降，并阻断新增和恶化。

扫描范围为 `packages/**/*.py`、`services/**/*.py`、`scripts/**/*.py` 和 `tests/**/*.py`。生成的 `*_pb2.py`、`*_pb2_grpc.py` 不进入扫描。

## 阈值

| 指标 | 阈值 | 实现 |
| --- | ---: | --- |
| 圈复杂度 | 10 | Ruff `C901` |
| return 数 | 6 | Ruff `PLR0911` |
| 分支数 | 12 | Ruff `PLR0912` |
| 语句数 | 50 | Ruff `PLR0915` |
| 固定位置参数 | 3 | Python AST |

`C901 <= 10` 和最多 3 个位置参数来自仓库 `AGENTS.md` 硬规则。`PLR0911/12/15` 使用 Ruff 默认阈值，作为高分支密度和超长函数的辅助信号；它们不替代对具体业务结构的判断。

位置参数按 AST 的 `posonlyargs + args + vararg` 计算，`*args` 作为一个变长位置参数。实例方法和类方法不计隐式 `self`、`cls`；keyword-only 参数不计入，因此 `def run(a, b, *, repository, logger)` 只算两个位置参数。`PLR0913` 统计总参数，会把 keyword-only 依赖注入一并计算，因此不用于本门禁。

## 基线语义

[`scripts/complexity_baseline.json`](../scripts/complexity_baseline.json) 的每条记录包含：

- 相对文件路径；
- 类、方法和嵌套函数组成的稳定限定名；
- 指标规则；
- 当前实际数值。

正常检查要求当前结果与基线完全一致：

- 新函数超限：失败；
- 现有函数指标升高：失败；
- 指标降低或违规消失：也提示更新基线并失败。

最后一项确保改进会立即固化。例如复杂度从 20 降到 15 后，基线必须收紧为 15，后续不能回升到 16。已消除的记录必须从基线删除，重新出现时会作为新增债务失败。

## 命令

执行门禁：

```bash
make complexity
```

代码重构降低或消除债务后，收紧基线：

```bash
make complexity-baseline-update
```

更新命令只接受降低和删除；检测到新增或恶化时拒绝写入。仍超限函数发生路径移动或重命名时，稳定标识会变化，需要在代码审查中显式核对对应基线变更，不能通过自动更新把它当作已有债务。

`make check` 和 CI 的 Backend Lint job 都执行该门禁。普通 Ruff 不再启用 `C901/PLR`，因此无需任何生产目录复杂度豁免；复杂度规则由这一条可审计路径统一负责。
